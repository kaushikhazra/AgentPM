## 5. core/planning.py — Plan Item Operations

- [x] VH worker implements `reorder_plan_item(item_id, new_position, actor)` in `core/planning.py` using the 4-step algorithm: (1) fetch item and record current plan_id and display_order; (2) delete item row temporarily; (3) call `_recompact_display_order(plan_id)` on the remaining N-1 items; (4) validate `new_position >= 1` and `<= N` where N is the post-removal item count — NOT the original count (W3); (5) call `_shift_items_down(plan_id, new_position)` then re-insert item at `new_position`; logs `reordered` activity with old and new positions; returns updated `PlanItem`. _TP-2_

## 7. core/planning.py — Plan vs Actual & Carry Over

- [x] VH worker implements `plan_vs_actual(plan_date, actor)` in `core/planning.py` — loads plan via `get_plan(plan_date=plan_date, actor=actor)`; for each planned item queries time_entries WHERE `actor = ? AND date(started_at) = ?` and sums `duration_minutes`; computes `delta_minutes = actual - planned` (None if `planned_minutes` is None); checks node's methodology for `is_terminal`; separately queries all time_entries on that date for the actor and subtracts plan node_ids to surface unplanned work; computes summary totals and `overall_delta`. NOTE: a time entry spanning midnight counts entirely toward `date(started_at)` — known behavior, not a bug; do not split entries across day boundaries (W5). _TP-7_
- [x] VH worker implements `carry_over_plan(source_plan_id, target_date, item_ids, actor)` in `core/planning.py` — loads source plan, raises `NotFoundError` if missing; raises `ValidationError` if `target_date <= source.date` (equality blocked; carrying to a past date that is still after the source date is intentionally allowed for retroactive plan reconstruction — W7); selects items: the provided `item_ids` if specified, else all items with `outcome IN ('pending', 'partial')`; records items with `outcome IN ('completed', 'dropped')` as skipped with reason `already_resolved`; creates target plan if not exists (same actor as source), otherwise fetches existing; gets max display_order in target; for each item to carry: skips with `already_in_target` if `node_id` exists in target plan; creates new `PlanItem` appended after existing items; updates source item to `outcome='carried_over', carried_to_plan_id=target_plan.id`; logs `carried_over` activity per item; returns `{source_plan_id, target_plan (full get_plan dict), carried_count, skipped}`. _TP-8_
